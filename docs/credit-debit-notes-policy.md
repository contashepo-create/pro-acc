# سياسة الإشعارات الدائنة/المدينة وقفل تعديل الفواتير (المحور الثاني)

> الحالة: مطبَّقة — ميجريشن `090-credit-debit-notes-invoice-immutability.sql`
> التاريخ: 2026-08-26

## القاعدة الأساسية

**فاتورة البيع بعد إنشائها مستند غير قابل للتعديل نهائياً.** لا توجد أي واجهة
أو نقطة API تسمح بتعديل بياناتها (بنود، كميات، أسعار، تواريخ، عميل، ضريبة،
إجمالي، ولا حتى الملاحظات)، والقفل مفروض على ثلاث طبقات:

1. **الواجهة:** صفحة الفواتير لا تقدم سوى (إنشاء / عرض / طباعة / إلغاء)،
   مع أزرار سريعة لإصدار إشعار دائن أو مدين بديلاً عن زر «تعديل» القديم.
2. **API:** حُذف `PUT /api/invoices/[id]` بالكامل (يرد Next.js تلقائياً
   405 Method Not Allowed). `PATCH` يسمح بحالة واحدة فقط: `cancelled`.
3. **قاعدة البيانات:** مُشغِّلات `BEFORE UPDATE` تمنع أي `UPDATE` يغيّر
   الحقول المحاسبية/التعريفية للفاتورة (`number, date, due_date, contact_id,
   project_id, subtotal, vat_rate, vat_amount, tax_rate, tax_amount, total…`)
   أو يعدّل/يحذف بنود `invoice_items` — حتى بصلاحيات الخدمة أو SQL مباشر.

## البديل النظامي: الإشعارات الدائنة والمدينة

كل تصحيح على فاتورة صادرة يتم بمستند مستقل بمرجع الفاتورة الأصل:

| النوع | متى يُستخدم | الأثر المحاسبي | الترقيم |
|---|---|---|---|
| **إشعار دائن** (Credit Note) | تخفيض/إرجاع/خصم بعد الإصدار | من ح/ الإيراد + ضريبة المخرجات ← إلى ح/ العملاء (يخفض رصيد العميل) | `CN-YYYY-####` |
| **إشعار مدين** (Debit Note) | زيادة/أعمال إضافية/نسيان احتساب | من ح/ العملاء ← إلى ح/ الإيراد + ضريبة المخرجات (يرفع رصيد العميل) | `DN-YYYY-####` |

- لكل إشعار قيد محاسبي مستقل متزن، وإلغاؤه يولّد قيداً عكسياً ولا يحذف شيئاً.
- عند ارتباط الإشعار بفاتورة، يُورث العميل والمشروع ونسبة ضريبة الفاتورة
  الأصل تلقائياً ولا يمكن تجاوزها.
- السبب إلزامي (بحد 1000 حرف) لكل إشعار — متطلب توثيقي ضريبي.

## صافي رصيد الفاتورة

```
الصافي = أصل الفاتورة + الإشعارات المدينة المعتمدة − الإشعارات الدائنة المعتمدة
المتبقي للتحصيل = الصافي − المدفوع
```

- سندات القبض (اليدوية وFIFO واعتمادات السندات والدفع الإلكتروني عبر
  `finalize_gateway_payment`) تخصّص ضمن **الصافي** لا الأصل — لا يمكن أن
  يتحصّل مبلغ يتجاوز صافي الفاتورة بعد الإشعارات.
- إشعار دائن جديد لا يجوز أن يتجاوز الصافي المتاح، فلا ينشأ رصيد دائن غير مقصود.
- الفواتير المعروضة للتحصيل في `vouchers/unpaid-invoices` تعرض
  `net_total` و`remaining` على أساس الصافي نفسه المفروض في قاعدة البيانات.

## قيود الإلغاء

لا يمكن إلغاء فاتورة:
- عليها أي تحصيل (سند قبض أو دفع إلكتروني)؛
- لها **إشعار دائن أو مدين معتمد** (ألغِ الإشعارات أولاً)؛
- ولا يمكن إعادة فتح فاتورة ملغاة مطلقاً (مُشغِّل القفل يمنعه).

## حقول النظام الوحيدة القابلة للتغيير آلياً

`status` (إلغاء/تحصيل)، `paid_amount`، `journal_entry_id`، `zatca_qr`،
`tax_snapshot`، `updated_at`، `deleted_at`، و`notes` (فقط لحظة الإلغاء).
أي شيء آخر يرفضه قاعدة البيانات برسالة توجّه المستخدم للإشعارات.
