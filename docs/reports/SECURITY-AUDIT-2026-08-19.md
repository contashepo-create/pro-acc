## 2. الملخص التنفيذي

**التقييم العام: جيد جداً — مستوى حماية أعلى بكثير من متوسط تطبيقات هذا الحجم.** لم يتم العثور على أي ثغرة **حرجة (Critical)** أو **عالية (High)**. النظام مبني على مبادئ صحيحة:

- كل الاستعلامات **معلمية (parameterized)** — صفر حقن SQL.
- صفر استخدام `dangerouslySetInnerHTML` — صفر ثغرات XSS كلاسيكية.
- عزل الشركات (Multi-tenant) مطبق في كل مسار وفي RPCs وفي triggers.
- المنطق المالي الحساس **داخل قاعدة البيانات** عبر RPCs ذرّية (atomic) مع أقفال `pg_advisory_xact_lock`.
- لا يوجد حذف فعلي للقيود — يُنشأ **قيد عكسي** بدلاً منه (ممارسة محاسبية صحيحة).

### 3.3 رفع الملفات — فحص معمّق (طلبك المحدد)

**سطوح الرفع في النظام: 4 فقط** (الإيصالات، شعار الشركة، مستندات العقود، النسخ الاحتياطي). لا توجد حقول رفع أخرى.

| السطح | الامتداد | فحص الحجم | فحص المحتوى (Magic Bytes) | الحصص | الفحص |
|---|---|---|---|---|---|
| `/api/upload/receipt` | JPG/PNG/PDF فقط من قائمة بيضاء | 5MB | ✅ نعم | ✅ مساحة الباقة إجبارية (0MB = رفض) | ✅ محمي جيداً |
| `/api/contracts/[id]` (مستندات) | enum صارم JPG/PNG/PDF | 10MB بعد فك base64 | ✅ نعم | ✅ مساحة الباقة | ✅ محمي جيداً |
| `/api/company/logo` | URL فقط (لا رفع) | — | `safeHttpsUrl` يرفض غير HTTPS والاعتمادات | — | ✅ |
| `/api/backup/upload` | JSON فقط | 25MB | HMAC كامل + سجل `backup_logs` + ملكية الشركة + إعادة تحقق RPC | — | ✅ ممتاز |

**النتيجة المكتشفة (🟠 متوسطة):** فحص Magic Bytes قابل للالتفاف بملفات Polyglot:

```ts
// src/lib/safe-input.ts
if (mime === 'application/pdf')
  return buffer.subarray(0, 1024).includes(Buffer.from('%PDF-'));   // ← ضعيف
if (mime === 'image/jpeg' || mime === 'image/jpg')
  return buffer[0] === 0xff && buffer[1] === 0xd8 && buffer[2] === 0xff; // ← 3 بايت فقط
```

**أثبتُّ ذلك عملياً في الـ fuzzer:**
- ملف `<html><script>alert(1)</script>` مسبوق بسطر تعليق يحتوي `%PDF-` → **يمر كـ PDF** ✅(ثغرة)
- ملف HTML يبدأ بـ `FF D8 FF` → **يمر كـ JPEG** ✅(ثغرة)
- فحص PNG صارم (8 بايتات صحيحة) ✅

**عوامل التخفيف الحالية:** التخزين خاص (bucket غير عام)، روابط موقّعة تنتهي خلال دقائق، `contentType` يُفرض من القائمة البيضاء، CSP يمنع التنفيذ، و`X-Content-Type-Options: nosniff` مفعّل. الخطر المتبقي منخفض لكن غير صفري (مثال: ضحية يفتح "إيصال" هو في الحقيقة HTML مُلغّم إذا تغيّر أي عامل تخفيف مستقبلاً).

**التوصية:** تحقق أعمق (PDF: التحقق من رأس `%PDF-` عند الإزاحة 0 + ذيل `%%EOF` ضمن آخر 1024 بايت أو فحص بنيوي بمكتبة مثل `pdf-lib`؛ JPEG: فحص `SOI` + `APPn`/`SOF` ورفض الملفات التي تحتوي `<!DOCTYPE`/`<script`/`<html` في أول 512 بايت)، وإضافة `Content-Disposition: attachment` عند التحميل.

## 4. فحص الحقن (Injection) على جميع الحقول

| النوع | الفحص | النتيجة |
|---|---|---|
| **SQL Injection** | فحص كل استدعاءات `query()`/`client.query()` — صفر ترميز قالب SQL بمتغيرات؛ كل القيم عبر `$1,$2...` أو PostgREST الذي يهرّب تلقائياً. Fuzz بأكثر من 20 حمولة SQLi على كل الحقول | ✅ **لا حقن** |
| **PostgREST Filter Injection** | `sanitizeEmailForFilter` + `sanitizeIpAddress` قبل أي `.or()` بمتغيرات مستخدم (مثال `a@b.com,or(id.neq.null)`) | ✅ |
| **XSS مخزّن** | صفر `dangerouslySetInnerHTML` في كامل الكود؛ React يهرّب تلقائياً؛ روابط الإعلانات تمر عبر `safeUrl` (رفض `javascript:`) | ✅ |
| **HTML Injection في تيليجرام/البريد** | قوالب الرسائل تملأ بمتغيرات مستخدم (أسماء عملاء…) دون تهريب HTML وترسل `parse_mode: HTML` | 🟡 منخفضة — اسم عميل يحتوي `<b>` مثلاً يعدّل شكل رسالة المدير (بدون تنفيذ)؛ يُنصح بالتهريب |
| **SSRF** | `safeHttpsUrl` يرفض كل ما ليس HTTPS صريحاً ويشمل userinfo؛ Fuzz بـ 15 حمولة (169.254.169.254، `//evil`، `user@pass`…) | ✅ كلها مرفوضة |
| **Path Traversal** | مسارات الكائنات في التخزين مفروضة `companyId/...` مع رفض `..` و`\`؛ `safeInternalPath`؛ Fuzz بـ 10 حمولات | ✅ |
| **XML Injection (ZATCA/UBL)** | `escapeXml` شامل (`& < > " '`)، هجوم `</cbc:Note><x>INJECTED</x>` **لم يفلح** — خرج مُهرَّباً | ✅ |
| **CSV Formula Injection** | `convertToCSV` في تصدير النسخ الاحتياطي لا يعطّل البادئات `= + - @` | 🟡 منخفضة — إضافة `'` قبل القيم النصية |
| **نموذج أولي (Prototype Pollution)** | مفاتيح `__proto__`/`constructor` تُرفض في المخططات الصارمة `.strict()` (Fuzz) | ✅ |
| **XXE/DTD** | لا توجد محركات XML طرف ثالث على مدخلات المستخدم | ✅ |
