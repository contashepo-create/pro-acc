# مقارنة المشروع بالبرامج العالمية — تحليل الفجوات (Gap Analysis)

**التاريخ:** 2026-08-12
**المعيار المرجعي:** منصات محاسبة/ERP للمقاولات عالمية — Sage 300 CRE، Viewpoint Vista، CMiC، Acumatica Construction، Procore Financial، Foundation Software، SAP S/4HANA، Oracle NetSuite، Odoo (مع وحدة ZATCA) — إضافةً لمنصات عامة مثل QuickBooks/Zoho/Tally.

---

## 1) الخلاصة التنفيذية

المشروع **متين بشكل ملحوظ كنواة محاسبية ERP للمقاولات**: تغطية محاسبية قوية (دليل حسابات، قيود، ميزانيات، قوائم مالية)، إدارة مشاريع و BOQ ومستخلصات وعقود باطن، رواتب وعمالة يومية، مخزون ومستودعات، فوترة مرحلية، بوابات دفع، بوابة عملاء، وأساس جيد من الأمان والتوثيق.

**الفجوات الكبرى مقابل البرامج العالمية تركز في أربعة محاور:**

1. **عُمق محاسبة المقاولات** (WIP، أوامر التغيير، الاحتجاز، فواتير AIA، رواتب معتمدة/نقابية، تكاليف المعدات).
2. **اكتمال امتثال ZATCA Phase 2** (التوقيع الرقمي CSID، الـ cryptographic stamp، وواجهة الـ Clearance/Reporting الفعلية مع Fatoora) — المشروع يغطّي المرحلة المبسّطة (QR + UBL XML) فقط.
3. **الترابط (Integrations)**: تغذية بنكية/Open Banking، وربط تقدير تكاليف/تسعير، وأدوات BI، وOpen API للبيانات.
4. **الحضور الميداني والموبايل**: تطبيق جوال أصلي بوضع عدم اتصال (offline) وإدخال وقت وحضور من الموقع، ونسخ للمستندات/توقيعات إلكترونية.

## 3) الفجوات — بالتفصيل ودرجة الأولوية

### 3.1 عُمق محاسبة المقاولات (الأعلى أولوية) 🟥
البرامج العالمية المخصّصة للمقاولات تميّز نفسها بهذه الوحدات، وهي **غائبة حالياً**:

| الميزة | الغرض | الحالة |
|--------|-------|--------|
| **WIP — العمل تحت التنفيذ** (تقرير Work-in-Progress مع تحليل over/under-billing) | مطلوب من شركات الضمان/البنوك لتمويل المشاريع | ❌ غائب |
| **أوامر التغيير (Change Orders)** مع أثرها على الميزانية | إدارة انحرافات العقود | ❌ غائب |
| **الاحتجاز (Retainage)** وتتبّع الاستحقاق والتحرير | ممارسة قياسية في عقود المقاولات | ❌ غائب |
| **فواتير AIA (G702/G703)** | معيار الفوترة الشهري في أمريكا — الأقل أهمية لسوق الخليج | ⚠️ اختياري |
| **الرواتب المعتمدة/النقابية (Certified/Prevailing Wage)** مع التقارير الحكومية (WH-347) | متطلّب للمشاريع الحكومية في أمريكا | ⚠️ اختياري للسوق الخليجي |
| **تكاليف المعدات (Equipment Costing)** تتبّع وتحميل تكلفة المعدات على المشاريع | إدارة أصول ثقيلة | ❌ غائب (يوجد fixed-assets عام) |
| **ربط التقدير/التسعير (Estimating → Budget)** | نقل ميزانية العطاء إلى الجوب كوستنغ تلقائياً | ❌ غائب |

### 3.2 اكتمال امتثال ZATCA Phase 2 (أولوية حاسمة للعميل السعودي) 🟥
البرامج المؤهّلة (مثل Odoo + l10n_sa_edi) تنفّذ المتطلبات التقنية الستة كاملة. المشروع يغطّي اثنين فقط:

| مطلب ZATCA Phase 2 | الحالة |
|--------------------|--------|
| UBL 2.1 XML | ✅ موجود (`ubl-builder`) |
| QR-TLV (المبسّط) | ✅ موجود (`qr-code`) |
| UUID لكل فاتورة | ⚠️ جزئي (يستخدم invoice.id كـ UUID، يحتاج UUID قياسي منفصل) |
| **الـ Cryptographic Stamp (توقيع ECDSA/rfc-3161)** | ❌ غائب |
| **التوقيع الرقمي للـ XML** | ❌ غائب |
| **واجهة Fatoora (Clearance B2B / Reporting B2C)** مع CSID والـ Production | ❌ غائب |
| **الأرشفة 7 سنوات للـ XML الموقّع** | ❌ غائب |
| إدارة أخطاء الـ Clearance بأكواد ZATCA وإعادة الإرسال | ❌ غائب |

> ⚠️ مع **موجات Phase 2 الممتدة حتى 2026** على كل المقيّمين لضريبة القيمة المضافة، هذا هو أكبر فجوة تجارية لهذا المنتج تحديداً.

### 3.3 الترابط (Integrations) 🟧
| الميزة | الغرض | الحالة |
|--------|-------|--------|
| **التغذية البنكية / Open Banking** (جلب حركات البنك تلقائياً وتطابقها) | تسوية بنكية شبه تلقائية | ❌ غائب (يوجد bank-reconciliation يدوي) |
| **Open API / Webhooks عامة** لبيانات العمل | ربط عملاء خارجيين وتكاملات | ❌ غائب (واجهات داخلية فقط) |
| **تصدير/استيراد بيانات شامل** (Excel/CSV متقدّم + نسخ احتياطي) | ترحيل ونسخ | ⚠️ جزئي (CSV في الجداول، نسخ احتياطي موجود) |
| **ربط أدوات التقدير/التسعير** (Sage Estimating, ProEst, Bluebeam) | تحويل العطاءات لميزانيات | ❌ غائب |
| **بوابة مدفوعات أوسع** | يوجد Moyasar فقط | ⚠️ محدود |
| **تقويم/بريد/Gantt مزامنة** | تكامل عملي | ⚠️ يوجد gantt داخلي فقط |

### 3.4 الموبايل والحضور الميداني 🟧
| الميزة | الغرض | الحالة |
|--------|-------|--------|
| **تطبيق جوال أصلي (iOS/Android)** | سهولة الاستخدام الميداني | ❌ يعتمد على PWA/متجاوب فقط |
| **وضع عدم اتصال (Offline)** | إدخال وقت/حضور في المواقع ضعيفة الشبكة | ❌ غائب |
| **إدخال الوقت/الحضور من الموقع (Field Time)** | عمالة ميدانية | ⚠️ جزئي (workers + timesheets عبر الويب) |
| **مستندات وتوقيعات إلكترونية** | موافقات عقود/مستخلصات | ⚠️ جزئي (approvals) |

### 3.5 الذكاء الاصطناعي والتحليلات 🟧
| الميزة | الغرض | الحالة |
|--------|-------|--------|
| **مساعد ذكي حقيقي (LLM)** | المساعد الحالي مطابقة كلمات مفتاحية (rule-based) وليس توليداً ذكياً | ⚠️ محدود |
| **تنبؤات/توقعات (Forecasting)** سيولة وربحية | قرارات مستقبلية | ❌ غائب |
| **لوحات BI قابلة للتخصيص وتصدير** | تحليلات متقدمة | ⚠️ أساسي فقط (Recharts) |
| **كشف شذوذ تلقائي** (احتيال/أخطاء إدخال) | حوكمة | ❌ غائب |

### 3.6 نزاهة البيانات والتدقيق 🟨
| الميزة | الغرض | الحالة |
|--------|-------|--------|
| **سجل تدقيق لكل معاملة مالية** (من غيّر/عدّل/حذف، قبل/بعد) | متطلّب حوكمة وشركات | ❌ يوجد audit_log للأدمن فقط، لا لكل كيان مالي |
| **نسخ/إصدارات للمستندات (Versioning)** | تتبّع تغييرات الفواتير/القيود | ❌ غائب |
| **منع حذف/تعديل القيود المؤرشفة (سنة مالية مقفلة)** | تكامل محاسبي | ⚠️ يوجد fiscal/closing جزئياً |
| **مصادقة محاسب/مراجع ثانية (Sign-off)** | إقرارات | ❌ غائب |

### 3.7 متعدد الكيانات واللغات 🟨
| الميزة | الغرض | الحالة |
|--------|-------|--------|
| **توحيد/دمج قوائم عدة شركات (Consolidation)** | مجموعات شركات | ❌ غائب (يوجد تقرير consolidation؟ — جزئي) |
| **لغات متعددة كاملة** (إنجليزية/عربية + أخرى) مع توطين تواريخ/أرقام | سوق أوسع | ⚠️ عربي أساساً + إنجليزية جزئية |
| **فروع (Branches)** ومراكز تكلفة متعددة الأبعاد | شركات كبيرة | ⚠️ يوجد branches/cost-centers جزئياً |

## 4) خارطة طريق مقترحة (بالأولوية)

### المرحلة 1 — «التميّز في السوق المستهدف» (أعلى أثر)
1. **إكمال ZATCA Phase 2 القياسي**: CSID (Compliance→Production)، التوقيع الرقمي XML، الـ Cryptographic Stamp، وواجهة Fatoora (Clearance/Reporting) + إدارة أخطاء وإعادة إرسال + أرشفة 7 سنوات للـ XML الموقّع. *(هذا يفتح السوق السعودي على نطاق واسع)*
2. **WIP + Or وأوامر التغيير + الاحتجاز**: تقارير تعادل Sage 300 CRE وتميّز المنتج كمنافس مقاولات حقيقي.
3. **سجل تدقيق مالي لكل كيان** + قفل/أرشفة الفترات المالية بمنع التعديل.

### المرحلة 2 — «الترابط والتحليل»
4. **التغذية البنكية/Open Banking** + تسوية شبه تلقائية.
5. **Open API + Webhooks** موثّقة للبيانات.
6. **مساعد ذكي حقيقي (LLM)** يحلل بيانات الشركة، ولوحات BI مخصّصة.

### المرحلة 3 — «الحضور الميداني والموبايل»
7. **تطبيق جوال أصلي بوضع Offline** مع إدخال وقت/حضور/تقارير يومية من الموقع.
8. **مستندات وتوقيعات إلكترونية** وتكامل أدوات تقدير/تسعير.

### أولويات لا يجب تأجيلها (حتى لو لم تكن «مميزة»)
- **مصادقة/مراجعة ثانية للعمليات الحسّاسة**، **تعديل سجل التدقيق**، و**أرشفة الأمان**.

## 5) ما يجب الحفاظ عليه (نقاط قوة لا تُفقد أثناء التطوير)
- **العزل متعدد الشركات (multi-tenant)** والالتزام بالسماح بقائمة بيضاء في كل دمج فلتر.
- **جودة الأمان والاختبارات** الحالية (360+ اختباراً) — استمر في توسيعها مع كل وحدة جديدة.
- **الامتثال الضريبي/المحاسبي** (سنة مالية، فوترة مرحلية) — أساس متين.
- **الوثائق القائمة** (INSPECTION_REPORT_AR، SECURITY-REVIEW، إلخ) كأصول معرفية.

---

## 6) توصية استراتيجية
بدلاً من بناء كل شيء دفعة واحدة، **ركّز على الفجوات الأعلى عائداً في السوق المستهدف (الخليج/السعودية)**: إكمال ZATCA Phase 2 + أدوات محاسبة المقاولات المتقدّمة (WIP/تغييرات/احتجاز) + سجل التدقيق المالي. هذه الثلاثة وحدها ترفع المشروع من «نظام محاسبة متكامل جيد» إلى «منافس مباشر لـ Sage/Viewpoint في السوق العربي»، وهي ما تميّز المنتجات العالمية المخصّصة للمقاولات.

## 7) ما تم تنفيذه فعلياً من هذه الفجوات (هذه الجلسة)

تم تنفيذ الجزء الأول القابل للتشغيل من الفجوات الثلاث المختارة (عُمق المقاولات + كشف الشذوذ + سجل التدقيق)، مع بنية جاهزة للتوسع:

### 1) عُمق محاسبة المقاولات
- `lib/construction.ts` — منطق محاسبي نقي قابل للاختبار: **WIP** (نسبة الإنجاز، الإيراد المستحق، زيادة/نقص الفوترة)، **الاحتجاز (Retainage)** مع سقف تعاقدي، **أوامر التغيير (Change Orders)**، و**توزيع تكاليف المعدات** على المشاريع حسب ساعات الاستخدام.
- Migration `026`: جداول `change_orders` و `equipment_costs` + أعمدة الاحتجاز على الفواتير.
- API: `/api/change-orders` (CRUD) و `/api/change-orders/[id]` و `/api/equipment-costs` و `/api/reports/wip`.
- صفحات: `change-orders` و `equipment` و `reports/wip` + إضافة للقائمة الجانبية.

### 2) الذكاء / كشف الشذوذ
- `lib/analytics/anomaly.ts` — كواشف حتمية قابلة للاختبار: **الفوترة المكررة**، **القيم الشاذة (outliers)**، **قفزات المصروفات**، **القيم غير الصالحة/السالبة**.
- API `/api/reports/anomalies` + صفحة `reports/anomalies`.
- ملاحظة: لا يزال المساعد الذكي rule-based؛ ترقية LLM الفعلية تتطلب مفتاح LLM وتُعدّ خطوة لاحقة مستقلة.

### 3) نزاهة البيانات
- `lib/audit.ts` — مساعد `logAudit` + `diffSummary` يكتب **سجل تدقيق مالي لكل شركة** (entity, action, before/after, summary) دون أن يفشل العملية أبداً.
- Migration `026` يتضمّن جدول `financial_audit_trails`.
- API `/api/financial-audit` + صفحة `financial-audit` + إضافة للقائمة الجانبية.
- **موصّل فعلياً** على: إنشاء القيود اليومية (journal)، وأوامر التغيير، وتكاليف المعدات.

### اختبارات جديدة
- `construction-depth.test.ts` (WIP/احتجاز/أوامر تغيير/معدات)
- `anomaly-detection.test.ts`
